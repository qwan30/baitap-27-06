1. Introduction

↓

1.1 Purpose

This Software Requirements Specification (SRS) document outlines the architectural, functional, and non-functional requirements for the AI Meeting Recorder system. It details the system context, actors, core use cases, and data models to ensure clear alignment across development, product, and QA teams.

1.2 Scope

The AI Meeting Recorder is a web-based platform that allows users to record or upload audio of meetings. The system utilizes Google's Gemini AI to transcribe the audio, generate comprehensive summaries, extract actionable items, and provide an interactive AI chat interface to query specific meeting details. It features a premium "glassmorphic" UI built with React, Vite, and Tailwind CSS, backed by an Express server and a local JSON database.

2. System Context

↓

2.1 Actors

  • End User: Interacts with the web application to record audio, review meeting summaries, query the AI Assistant, and export meeting notes.
  • React Frontend: Captures audio via the MediaRecorder API, visualizes waveforms, and renders Markdown results dynamically.
  • Express Backend: Acts as the intermediary API gateway, manages local JSON database storage, and orchestrates calls to the Gemini API.
  • Gemini AI (GoogleGenAI): Processes audio files multimodally to generate accurate transcripts, structured summaries, and action item lists.

5. Interfaces

↓

5.1 API Interface (REST)

The Express backend exposes the following primary endpoints:

  • POST /api/v1/auth/register - Registers a new user. Expects {name, email}.
  • GET /api/v1/meetings - Retrieves a lightweight list of meetings for the dashboard. Excludes heavy Base64 audio strings to optimize network load.
  • POST /api/v1/meetings/:id/process - Core processing route. Expects { audioBase64, durationSec, mimeType }.
  • POST /api/v1/meetings/:id/regenerate - Re-runs the summary generation based purely on the existing transcript text.
  • POST /api/v1/meetings/:id/ask - Interactive chat route. Expects { question }.
  • GET /api/v1/meetings/:id/export?format=markdown - Generates and serves a formatted Markdown string of the meeting.

5.2 External Integrations

Google Gemini API: Integrated via the @google/genai SDK. The system utilizes the gemini-3.5-flash model for its speed and multimodal capabilities, passing audio data inline and enforcing strict JSON output via prompt instructions and responseMimeType: 'application/json' configuration.

7. Assumptions and Dependencies

↓
IDAssumption / DependencyImpact
AD-001Gemini API AvailabilityThe system heavily relies on the Gemini API. If the API is down or the provided API key is invalid, the system automatically falls back to static high-fidelity simulated data to prevent application crashes.
AD-002Local File StorageCurrently uses a flat JSON file (meetings-db.json) for database operations. This is sufficient for prototype/local execution but lacks concurrency controls required for production deployment.
